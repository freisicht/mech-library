## Phase 1 — Scraper & Importer

**Goal:** A reproducible pipeline that fills a MySQL database with all BattleMech and OmniMech Alpha Strike data plus locally-stored images.

### Scope

- Mechs and OmniMechs only (filter on Type id `18` plus any Mech-adjacent type id discovered during the crawl — verify before extending).
- Three CLI commands:
  - `mul:scrape` — fetch raw JSON from MUL into `data/raw/`. Idempotent, cache-aware.
  - `mul:import` — read `data/raw/` and upsert into MySQL. Idempotent on MUL `Id`.
  - `mul:images` — download images referenced by units to `public/images/units/`. Skip if file exists & content hash unchanged.
- Two seed commands:
  - `mul:seed-factions` — parse `/Faction/Index` into `factions` table.
  - `mul:seed-eras` — parse `/Era/Index` into `eras` table.

### Tasks

- [x] **DB schema** — design + migration. Tables: `units`, `unit_abilities`, `factions`, `eras`, `unit_types`, `roles`, `technologies`. Document in `docs/SCHEMA.md` as you go (rationale, not just DDL).
- [x] **Perpl setup** — schema XML, generate Model classes into `generated-classes/App/Model/`. Committed. PSR-4 mapped via `generated-classes/App/` base dir.
- [x] **Crawler** — central `MulClient` with rate limit + disk cache + UA header. All HTTP to MUL goes through it. Unit-tested with mocked Guzzle handler.
- [x] **Pager** — iterate `(Type, Tonnage)` buckets per `docs/MUL_API.md`. Resume-safe: a finished bucket is not refetched (cache hit = skip).
- [x] **Importer** — read `data/raw/*.json`, upsert by `mul_id`. Parse `BFAbilities` into `unit_abilities`. Keep raw `BFAbilities` string on `units`.
- [x] **Image downloader** — separate command, separate cache. Polite timing. Stores SHA-256 hash, skips no-op rewrites.
- [x] **Tests** — unit tests for `MulClient` (cache hit/miss, rate limit, error handling), `BFAbilities` parser, `Importer::upsert` (live MySQL test DB, cleans up fixtures).
- [x] **Static checks** — `composer test` runs phpunit + phpstan (level 6) + php-cs-fixer --dry-run, all green.
- [ ] **Update docs** — `docs/SCHEMA.md` finalised, `docs/PLAN.md` ticked, `README.md` quick-start verified end-to-end.

### Notes / gotchas (added during implementation)

- **Perpl model output dir**: Perpl 2.x always generates into `generated-classes/` regardless of `outputDir` in `propel.php`. Workaround: PSR-4 maps `App\\` → `["src/", "generated-classes/App/"]`.
- **`generated-conf/loadDatabase.php`** is auto-generated by `vendor/bin/perpl model:build` and must be committed (it registers TableMap classes with the Propel ServiceContainer).
- **Type id 45 doesn't exist** — confirmed empty by the first real crawl (2026-04-26). MUL has no separate OmniMech type: OmniMechs (1029 of them, e.g. Timber Wolf) are filed under Type 18 (BattleMech) and identified via the `OMNI` token in `BFAbilities`. `Pager` default is `[18]`.
- **MySQL reserved word**: `long` in `unit_abilities` needs backtick quoting in the migration SQL.
- **Propel `setCost()` / `setMulRelease()`** expect `string|null` for BIGINT/DECIMAL columns — cast via `(string)` before passing.

### Definition of done

- `composer install && bin/console mul:scrape && bin/console mul:import && bin/console mul:images` from a clean clone produces a populated DB and image directory in <10 minutes.
- `composer test` green.
- Tag `v0.1.0` on `main`.

## Phase 2 — Filterable web UI

**Goal:** A served web page at `http://localhost/mech_library/` (Apache vhost on `public/`) showing all units in a fast filterable table.

### Scope

- Single-page table (Twig-rendered shell + JS-driven table). DataTables or Tabulator — pick one in an ADR.
- Server-side filtering and paging (the dataset is small enough for client-side, but server-side keeps URLs shareable and is the same plumbing the force builder will need).
- Filters (the user has specific ones in mind — **ask before building**):
  - Tonnage range, PV range, Move (incl. jump), TMM
  - Type, Role, Tech base
  - Damage at S/M/L (min)
  - Abilities (multi-select including AND/OR semantics)
  - Era / availability date range
  - Free-text on Name / Class / Variant
- Detail view per unit (Twig page).
- No auth, no accounts. Local single-user app.

### Tasks (high level — refine when phase starts)

- [x] Slim 4 + Twig wired up via `public/index.php`. PHP-DI container in `src/Web/ContainerFactory.php`. App factory in `src/Web/AppFactory.php` reused by tests.
- [x] `UnitRepository` with raw-PDO filter builder (not Propel ORM — see gotchas). Composable WHERE clause from `FilterInput` DTO.
- [x] `GET /` — table view + filter form (Twig + Tabulator shell).
- [x] `GET /units/{id}` — detail view with abilities breakdown table.
- [x] `GET /api/units` — JSON for Tabulator (`{total, last_page, data[]}`).
- [x] CSS: Pico.css 2.x + Tabulator's own CSS. ADR 001 + 002 in `docs/decisions/`.
- [x] Feature tests via Slim's in-process `App::handle()` — live MySQL DB, fixtures cleaned up in tearDown.

### Notes / gotchas (added during implementation)

- **Propel `prepare()` returns `StatementWrapper`**, not `PDOStatement`. Return type of `exec()` in `UnitRepository` must be `\Propel\Runtime\Connection\StatementInterface`. PHPStan stubs were fine, but the runtime blew up with a `TypeError`.
- **MySQL LIMIT/OFFSET with named PDO params** — named params are bound as strings; `LIMIT '50' OFFSET '0'` is a syntax error. Embed integer LIMIT/OFFSET directly in the SQL string (safe because they are PHP `int` values).
- **Twig has no `|string` filter** — use `~ ''` (string concatenation) to coerce a value to string in Twig templates.
- **Detail template field names** — `findById()` returns raw DB column names (`bf_move`, `bf_tmm`, etc.); the list endpoint aliases them (`move`, `tmm`). Template uses the raw names.
- **Worktree `.env` symlink** — `.env` is gitignored and only exists in the main repo. Tests in the worktree need `ln -sf /path/to/main/.env .env` (one-time, developer setup).
- **Ability test isolation** — when filtering by a common ability tag against a fully-populated DB, page 1 may not contain the fixture unit. Combine with `search=Test Atlas` to guarantee fixture hits.

## Phase 3 — Force builder

**Goal:** Compose Alpha Strike formations from the unit list, enforce formation-type rules, track PV budgets, and print a clean summary sheet.

Reference ADR: `docs/decisions/003-force-builder-scope.md`.

### Scope

Two-level hierarchy: **Army** → **Formation**. Both named, persisted in DB.  
~35 canonical Alpha Strike formation types with a data-driven rules engine.  
Live force panel visible while browsing. Unit suggestion helper reuses Phase 2 filters.  
Print view: HTML + print-CSS only (no PDF generation).

### Tasks

**DB & backend**

- [x] SQL migration: `armies`, `formations`, `formation_units` tables. Document in `docs/SCHEMA.md`.
- [x] Perpl schema XML update + regenerate model classes.
- [x] Formation type registry: PHP config (~35 AS types) with rule descriptors (unit count bounds, category/role constraints, special-ability requirements).
- [x] `FormationRulesEngine` service: given a formation type + unit list → compliant bool + list of unmet requirements.
- [x] `ArmyRepository` / `FormationRepository`: CRUD, fetch with units and compliance result.
- [x] API endpoints:
  - `GET  /api/armies` — list with nested formations
  - `POST /api/armies` — create
  - `GET  /api/formations/{id}` — formation + units + compliance + PV summary
  - `POST /api/formations` — create (optionally under an army)
  - `POST /api/formations/{id}/units` — add unit
  - `DELETE /api/formations/{id}/units/{unitId}` — remove unit
  - `PUT /api/formations/{id}` — rename, change type, change PV budget

**Frontend**

- [x] Base layout: persistent force panel (Twig partial, right sidebar or collapsible bottom drawer).
- [x] Panel shows: active formation name + type, unit list with per-unit PV, PV sum / remaining, S/M/L damage totals, compliance indicator + unmet-requirement list.
- [x] Army/formation selector in panel header: create new, switch active, move formation into/out of army.
- [x] "Add to force" button on Tabulator table rows (formatter) — adds to active formation via AJAX.
- [x] "Add to force" button on unit detail page.
- [x] Suggestion helper: "Show matching units" button pre-fills filter form (PV max = remaining budget + formation-type constraints as filters).
- [x] Print view: `GET /formations/{id}/print` — Twig template, print-CSS, no JS required.

**Quality**

- [x] Unit tests: `FormationRulesEngine` (at minimum one compliant + one non-compliant case per rule dimension).
- [x] Feature tests: CRUD endpoints (create army, add formation, add/remove unit, compliance response).
- [x] `composer test` green (phpunit + phpstan level 6 + php-cs-fixer --dry-run).
- [x] `docs/SCHEMA.md` updated, `docs/PLAN.md` tasks ticked, `README.md` quick-start still valid.

### Notes / gotchas (added during implementation)

- **`Propel::getConnection()->getLastInsertId()` does not exist.** PHP 8.5 ships `Pdo\Mysql` which lacks this method. Use Perpl ORM `->save()` + `->getId()` for INSERT operations; reserve raw PDO for SELECTs/UPDATEs/DELETEs.
- **Worktree vendor path.** Git worktrees share no `vendor/` with the main repo. Symlinking `vendor/` from the main repo breaks PSR-4 autoloading (Composer bakes the absolute base dir into `autoload_psr4.php`). Run `composer install` inside the worktree and commit nothing extra — `vendor/` stays gitignored.
- **PHPStan: two `@param` tags on one line.** PHPStan only reads the first `@param` in a single-line docblock (`/** @param A $a @param B $b */`). Always use multi-line docblocks when annotating more than one parameter.
- **Formation type rules marked `[VERIFY]`.** ~15 of the ~35 canonical formation types have rules that are best-effort from memory. They need to be checked against the Alpha Strike Companion or Commander's Edition rulebook. Correct entries in `src/Formation/FormationTypeRegistry.php`; tests will catch regressions.
- **Single-active invariant.** MySQL lacks partial unique indexes so the constraint that at most one formation is active is enforced by `FormationRepository::setActive()`. If multiple processes could write concurrently (they can't — single-user app), a transaction would be needed.

### Definition of done

- Army → Formation hierarchy works end-to-end: create, populate, view, print.
- Formation rule compliance displayed live for at least 10 representative formation types.
- Suggestion helper pre-fills filters correctly for the active formation's constraints.
- `composer test` green.
- Tag `v0.3.0` on `main`.
