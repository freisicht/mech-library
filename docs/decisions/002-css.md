# ADR 002 — CSS: Pico.css

**Status:** Accepted  
**Date:** 2026-04-27

## Context

The UI is a single-page table with a filter panel and a detail view. It will
be used on a single local machine; no mobile breakpoints are required. The
constraint is: no build step, no preprocessor, minimal weight.

## Decision

**Pico.css 2.x** (classless variant).

Reasons:
1. Classless — standard HTML elements (`<form>`, `<input>`, `<select>`,
   `<table>`, `<details>`) get sensible styles with zero extra markup.
2. ~10 KB minified; single CSS file, no fonts, no icons.
3. Ships a dark theme via `data-theme="dark"` on `<html>` — easy toggle later.
4. Form elements (range inputs, multi-selects, text fields) look reasonable
   out of the box, which covers most of our filter bar.
5. No class naming convention to learn; Twig templates stay readable.

Tabulator ships its own table CSS (`tabulator_midnight.min.css` for dark or
`tabulator.min.css` for light), so the grid is self-styled and does not
conflict with Pico's `<table>` styles.

## Consequences

- `public/assets/css/pico.min.css` vendored locally.
- Tabulator's own CSS also vendored (`public/assets/css/tabulator.min.css`).
- Custom overrides go in `public/assets/css/app.css` (hand-rolled, minimal).
- If the UI needs heavier customisation in Phase 3, Pico can be swapped for
  hand-rolled CSS without touching PHP or Twig structure.
